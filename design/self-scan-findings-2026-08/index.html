    Self-scan triage — running the corpus method against our own tree¶

    Date: 2026-08-17. Scope: python-security, owasp-top-10, supply-chain-security — the three packs the dev repo self-scans with. 67 findings across 29 rules.

    Why this was worth doing¶

    Three false positives surfaced in a single day (SCS-BUILD-001, SCS-CI-004, PY-SEC-014), and every one of them surfaced only because a PR happened to touch the file. PY-SEC-014 had been wrong since it was written and sat undetected in the licensing service. The gate only ever looks at changed files, so a bad rule in an untouched file is invisible indefinitely.

    The corpus harness already exists for external repos. Pointing the same method at our own tree costs one scan. The oracles in scripts/corpus/invariants.py cannot find this class of bug — they compare Sentrik against itself and catch walker/exclude errors. Finding a rule whose pattern is simply wrong requires looking at what it matched.

    Findings in demo/ are excluded from what follows: that project contains deliberate vulnerabilities and Sentrik correctly flags all of them.

    Confirmed false positives¶

    1. OWASP-A03-006 no-exec — fires on the standard JavaScript regex API¶

    critical, pattern \bexec\s*\(, glob **/*.{py,js,ts,jsx,tsx,rb,kt}.

    The rule means Python's exec(). The pattern matches any method named exec:

    Code Fires What it actually is
    /foo(\d+)/.exec(input) yes The standard JS regex API
    while ((m = pattern.exec(text)) !== null) yes Same, the canonical iteration idiom
    cp.exec(cmd, opts, cb) yes Node child_process — a different vuln with different remediation
    db.exec("PRAGMA journal_mode=WAL") yes sqlite DDL
    exec("os.system(x)") yes the actual vulnerability

    Hit in our own tree at vscode-extension/src/extension.ts:1696. In any regex-heavy JavaScript codebase this fires continuously, at critical.

    Fix: restrict the glob to Python/Ruby, or require the Python call shape. .exec( with a receiver is never Python's builtin.

    2. PY-SEC-001 / OWASP-A03-005 no-eval — fires on prose¶

    critical, pattern \beval\s*\(. At src/guard/reporters/executive_summary.py:148:

    kind of issue is in general (e.g. an <code>eval()</code> call is always Critical).

    That is explanatory text in an HTML report template, flagged as a critical injection vector. Same shape as the \bassert\b and \bgoto\b problems fixed in the medtech packs: a bare keyword match with no code context.

    3. STD-003 no-hardcoded-secrets — fires on documentation placeholders (8 findings)¶

    critical, all in license-server/README.md:

    export GUARD_LICENSE_SECRET="your-secret-here"
export STRIPE_WEBHOOK_SECRET="whsec_..."
fly secrets set GUARD_LICENSE_SECRET="your-production-secret"

    These are setup instructions telling operators to use env vars — the remediation the rule itself recommends. Same self-defeating shape as HIPAA-164.312-a1 flagging patient_id.

    Fix: exclude obvious placeholder values (your-..., <...>, ..., changeme, xxx) and consider whether **/*.md belongs in the glob at all.

    4. OWASP-A02-003 — fires on a sentinel that means "no key"¶

    src/guard/providers/llm_openai.py:39: self._api_key = "proxy-no-key-required". A literal whose entire purpose is to say there is no credential.

    5. Pack YAML matching its own rule definitions (again)¶

    SCS-DEP-002 and SCS-BUILD-002 fire on src/guard/packs/iec_81001_5_1/pack.yaml:238 and src/guard/packs/supply_chain_security/pack.yaml:180 — the lines that define the patterns being hunted. STD-001 (no-todo-comments) does the same on src/guard/core/drift_analyzer.py:374, a regex containing the word TODO.

    This is the SCS-CI-004 case, already suppressed for SCS-CI-* and SCS-BUILD-001. The suppression needs to cover the whole class, not one rule at a time — a rule definition is data, not an instance of what it describes.

    6. SCS-DEP-002 — fires on an error message¶

    demo/run_demo.sh:48: 

    err "Could not find 'sentra' command. Install with: npm install -g sentra"
    A string telling a user how to install something is not an unpinned install.

    7. SCS-CI-006 — all_patterns has no proximity requirement¶

    Reported at templates/gitlab-ci-sentrik.yml:1, which is a comment: # Sentrik compliance gate for GitLab CI/CD.

    all_patterns is a file-level AND: pattern A (security|scan|sentrik|...) matches line 1, pattern B (allow.failure|continue-on-error) matches somewhere else entirely, and the finding is pinned to the first match. Nothing requires the two to be the same CI step.

    Any CI file that mentions "security" or "scan" anywhere and uses continue-on-error anywhere will fire, however unrelated. This is a rule-engine semantics issue rather than one bad pattern, and it affects every rule using all_patterns.

    8. REQ-DRIFT-* — treats binary and generated files as source¶

    high severity, on:

    project_management/AI_SDLC_Guard_Demo_Plan.docx
project_management/AI_SDLC_Guard_Product_Plan.pptx
project_management/AI_SDLC_Guard_Task_Tracker.xlsx
~$_SDLC_Guard_UX_Changelog.docx      <- a Word lock file
site/sitemap.xml.gz                  <- gzip
_dash_debug.js

    "Source file X is missing requirement Y" for a PowerPoint, and for a temporary lock file Word creates while a document is open. The drift analyzer needs the same non-source suffix filter that _filter_scannable gained in #158.

    9. OWASP-A05-001 — schema namespace URL¶

    src/guard/core/notifications.py:271: "$schema": "http://adaptivecards.io/schemas/adaptive-card.json"

    A JSON Schema identifier, not a data transmission — the same class as the RFC 2606 and w3.org exclusions added in #159. adaptivecards.io (and schema namespaces generally) belong in that allowlist.

    True positives worth acting on¶

    Not everything here is noise:

    • PY-SEC-008 / OWASP-A03-004 — subprocess.run(cmd, shell=True, ...) at scripts/run_manual_tests.py:21. Real, in our own tooling.
    • SCS-DEP-001 — unpinned pip install in scripts/build-binary.sh:18, azure-pipelines.yml:67 and automation/scripts/setup.sh. Real supply-chain exposure in our own build.

    Suggested order¶

    1. OWASP-A03-006 glob/shape — highest volume on any JS codebase, and critical.
    2. Placeholder handling in STD-003 / OWASP-A02-003 — affects every user with a README.
    3. REQ-DRIFT-* non-source filter — currently emits high findings about PowerPoints.
    4. Class-wide suppression for pack YAML self-matches.
    5. all_patterns proximity — the largest change, and a design decision rather than a fix.
    6. Fix the two real ones in our own build scripts.

    Making this repeatable¶

    This was a single manual scan. It should be a corpus phase: add the Sentrik tree as a target in scripts/corpus/corpus.yaml so a self-scan runs alongside the external repos and compare_runs.py shows rule-level drift release over release. The gate will never catch this class on its own, because it only ever looks at files a PR happened to touch.
